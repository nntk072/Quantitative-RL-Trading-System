# Security policy

## Supported versions

Security fixes are considered for the current `main` branch. This project does
not currently publish a release support matrix.

## Reporting a vulnerability

Do not publish exploit details, credentials, account identifiers, or
unreleased vulnerability information in a public issue or pull request.

GitHub private vulnerability reporting was verified as enabled on 2026-11-01.
Use the repository's **Report a vulnerability** action to submit details
privately; see GitHub's guide to
[private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).
Do not send technical details in a public issue or pull request.

Include the affected revision, component, impact, and a minimal reproduction
only after a private channel is established. The maintainer will coordinate a
response and disclosure timeline; no response-time guarantee is currently
published.

This policy covers software vulnerabilities in the repository and its
maintained integrations. Trading losses, broker outages, and differences
between historical simulation and live execution are operational risks, not
security reports; see the [project limitations](docs/architecture/risks_and_technical_debt.md).
