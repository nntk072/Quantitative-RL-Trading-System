Build a correctness-first, high-performance quantitative research platform with reusable native trading/simulation kernels, efficient data and storage, optimized RL training, a resource-aware experiment runtime, reproducible statistical evaluation, and a separately gated production platform. Use established open-source implementations wherever they reduce work without weakening domain semantics. Large refactors are authorized as a design approach; no requirement to minimize diff size. Preserve public interfaces only where they serve real consumers, documented compatibility, or reproducibility. Remove redundant implementations after verified migration, not before. Do not confuse maximizing resource utilization with maximizing scientifically valid experiments per GPU-hour.

Read `AGENTS.md`, `.agents/architecture.md`, applicable `.agents/rules/`, and current source and tests. Retain the existing repository's authority for permission, operating rules, and research methodology. This plan does not authorize commits/pushes, deleting artifacts, spending money, real orders, deployment, changing Slurm limits, or canceling Slurm jobs. Never execute `scancel`. Keep all heavy work inside the authorized compute allocation. No per-variant short Slurm steps. Preserve existing work and active runs; do not change code beneath a running process. Use a separate pinned checkout/worktree if authorized by repository rules; otherwise defer conflicting modifications until safe. Do not create unnecessary branches, duplicated experiment implementations, or repeated agent plans. Keep one plan, one machine-readable completion ledger, and one evidence index. Follow actual user authorization for final commit/push; no incremental pushing by default.

### 0.1 Mandatory invariants (INV)

- INV-DATA: UTC canonical event time plus source clock, availability time, stable tie-breaker and source identity; no incomplete higher-timeframe data; no backward fill or implicit future inputs; session labels are masks, not row deletion; retain explicit missing intervals; train-only fitted state; purged chronological folds with label horizon and embargo; locked/exposed 2026 reporting data never used for tuning, pruning, checkpoint selection or performance-driven redesign of scientific semantics.
- INV-DOMAIN: action request, intent, order, fill and position are distinct. Explicit units, tick/lot sizes, rounding, costs, bid/ask, account currency, risk floors, daily reset and breach latches; no weakened hard limits. Preserve current event ordering: advance and mark existing positions, process protective levels, then apply the current action at its declared fill point. A new position must not see earlier price movement. Ambiguous intrabar paths must be declared, not fabricated.
- INV-RL: versioned action and observation schemas, field order, candidate IDs, mask polarity, no-trade behavior, reward components, termination/truncation, bootstrapping and policy-version semantics. PPO must remain on-policy; SAC replay behavior must remain declared. Do not alter model/update geometry, exposure or budget merely to claim speed. Distinguish exact, numerical and statistical equivalence.
- INV-EVIDENCE: frozen run design, exact source/config/data/backend/seed identities; preserve negative, invalid, incomplete, breached and no-trade outcomes. All reporting derives from reconciled immutable ledgers; old evidence from before 2026-11-15 clean restart is not a current empirical result. Never relabel exposed data as untouched. An engineering benchmark is not scientific evidence.
- INV-COMPUTE: use live cgroup/Slurm limits, architecture-matched wheels, bounded persistent workers, actual allocated CPU/GPU/RAM, no per-worker `srun`, no rapid retries, no artificial job padding, no destructive cleanup. Default one GH200 per task; only approved resources; current repository limits remain authoritative. Node-local staging must preserve durable copies on scratch.
- INV-OPS: fail closed on invalid configuration, schema mismatch, stale data or ambiguous execution; no silent backend fallback, unchecked unsafe Rust, silent partial success or secret logging. Live deployment is independent of offline scientific readiness.

Integration owner reviews cross-language and research semantics. One final consolidated handoff; preserve all failures.

Gates: **OFFLINE** = blocks native/offline readiness or 20M evidence when affected; **BENCH** = engineering qualification before switching defaults; **PRODUCTION** = separate live gate, not a prerequisite for offline 20M; **PRODUCT** = final website/application gate. Optional technology trials have explicit promotion criteria; failure must result in documented rejection and a viable retained implementation, not an endless rewrite.
